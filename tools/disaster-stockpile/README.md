# 防災備蓄シミュレーター

家族構成と備蓄日数から必要な備蓄品の数量を算出し、購入日を記録して入れ替え時期を管理するブラウザ向けツールです。

## 概要

- 大人・子供（2〜12歳が目安）・乳児・犬・猫の人数（頭数）と備蓄日数を入力すると、リアルタイムに必要数量が更新されます。
- 品目ごとに優先度と数量の算出式を表示します。
- 品目ごとに購入日を記録すると、期限日と残り期間を表示します。期限が近いものが上に並びます。
- 商品リンクは [assets/affiliate.js](../../assets/affiliate.js) 経由で Amazon・楽天・メルカリを提示します。

## 主な機能

- **数量の算出**: 品目ごとに定義した1日あたりの必要量を、構成員の人数と備蓄日数から積み上げて算出します。端数は分割購入できないため切り上げます。
- **算出根拠の表示**: 数量の下に `大人2名 ✕ 1日2食 ✕ 7日` のような式を添え、目安の妥当性を利用者が判断できるようにします。切り上げが発生した場合はその旨を付記します。
- **優先度の表示**: 品目ごとに「必須」「推奨」「あると安心」のいずれかを表示し、何から揃えるべきかを示します。
- **ペットを含めた算出**: 犬・猫の飲料水とフードを人の分と合わせて算出します。ペットを含む備蓄計算に対応した公開ツールは多くありません。
- **期限の管理**: 保存期間の目安から期限日を算出し、残り期間を年・月・日のうち適切な単位で表示します。期限切れと90日以内の件数を警告として表示します。
- **ローリングストックの案内**: 古いものから使って買い足す運用を促す説明を期限管理セクションに常時表示します。

## 数量の算出モデル

必要数量は次の合計で求めます。各品目はこのうち必要なものだけを持ちます。

```
  1日あたりの必要量（構成員ごと）× 人数（頭数）× 備蓄日数
+ 1週間あたりの必要量（構成員ごと）× 人数（頭数）× 備蓄日数 ÷ 7
+ 世帯単位の1日あたり必要量 × 備蓄日数
+ 1人あたりの固定量 × 人数
+ 世帯あたりの固定量
```

`perWeek`（1週間あたり）は、公的資料が週単位で目安を示している品目（カセットガスなど）を、資料どおりの数値のままデータに持たせるためのフィールドです。

軍手や液体歯磨きのように乳児には不要な品目は、`perPersonExcludesInfant` を指定して乳児を人数から除きます。

なお「子供」は2〜12歳程度、「乳児」はミルクやおむつが必要な時期を想定した区分です。

### 優先度

品目は `importance` で3段階に分けています。表示順を決める `priority` とは別の値です。

| 値 | 表示 | 考え方 |
| --- | --- | --- |
| 1 | 必須 | ライフラインが止まった直後から欠かせないもの（水・主食・簡易トイレなど） |
| 2 | 推奨 | 数日の在宅避難で不足しやすいもの（熱源・乾電池・保温用品など） |
| 3 | あると安心 | 生活の質を保つもの（ラップ・マスクなど） |

## データの保存について

入力内容と購入日はブラウザのローカルストレージ（キー `disaster-stockpile.v1`）に保存され、次回アクセス時に復元されます。サーバーには送信されません。

保存データが壊れている場合や、プライベートモードなどで書き込めない場合は、警告をコンソールに出したうえで初期状態のまま動作を継続します。

## 広告表記について

- **PR表記**: 景品表示法（ステマ規制）に対応するため、商品リンクの直前に `[PR] アフィリエイト広告を利用しています` を表示します。
- **アソシエイト表記**: Amazonアソシエイト・プログラム運営規約で義務付けられている表記と、楽天アフィリエイトへの参加をページ下部に常時表示します。
- **価格の非表示**: PA-API を利用していないため、規約上価格を掲載できません。商品データにも価格を持たせていません。

## 免責について

算出値は公的資料の目安にもとづく概算であり、資料に該当する記載がない品目は当サイト独自の目安である旨を品目ごとに明示しています。備蓄の考え方や地域固有のリスク、避難所・避難経路については自治体および公的機関の情報を確認するよう案内しています。医薬品は扱っておらず、常用薬やアレルギー対応食品については医師・薬剤師への相談を促しています。

## 技術メモ

- Tailwind CSS と lucide を CDN から読み込む、ビルド不要の単一HTML構成です。
- 商品データは `Affiliate.registerProducts()` で登録します。JSON ではなく JS ファイルにしているのは、`file://` で直接開いた際に `fetch` が CORS で失敗するのを避けるためです。
- 出典データは商品データと同じファイルに `sources` として持たせ、`Affiliate.getSources()` / `Affiliate.sourcesFor()` で取り出します。共通モジュールを変更したため、読み込み側のバージョンは `?v=7` に上げています。
- [tools/pet-timeline](../pet-timeline/README.md) の消耗品補充リマインドと同じ構造を、期限管理に転用しています。
- 商品カードは DOM API で構築しており、`innerHTML` に商品データを流し込んでいません。

## 商品データの追加・変更

[../../data/products/disaster.js](../../data/products/disaster.js) を編集します。数量の算出フィールドと保存期間の意味はファイル冒頭のコメントに記載しています。価格は規約上掲載できないため、**商品データに価格を持たせないでください**。
